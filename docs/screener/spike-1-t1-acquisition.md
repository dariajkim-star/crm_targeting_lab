# Spike 1 · T1 — SEC 취득 경로 확정 (AC1)

- **일자**: 2026-07-28
- **판정**: ✅ **주석 레벨 데이터 도달 가능** — AC1 통과. 스파이크 축소 없이 T2~T5 진행 가능.
- **범위 주의**: 이 문서의 모든 수치에는 **모집단과 취득 창**이 붙어 있다. 창을 바꾸면 수치가
  바뀐다(crm 교훈 "환경 의존은 수치에 병기").

## 1. 확정된 취득 경로 3종

| 경로 | URL 패턴 | 용도 |
|---|---|---|
| frames API | `https://data.sec.gov/api/xbrl/frames/us-gaap/{tag}/USD/{period}.json` | 한 개념의 **전 filer 값 한 번에** — 커버리지 격차 1차 스캔 |
| 재무제표 벌크 | `https://www.sec.gov/files/dera/data/financial-statement-data-sets/{q}.zip` | 본문 태그 + `sub` 메타. 분기당 **79~128MB** |
| **주석 벌크** | `https://www.sec.gov/files/dera/data/financial-statement-**notes**-data-sets/{period}_notes.zip` | **주석 레벨 태그** — 이 스파이크의 핵심 원료 |

### 접근 규약 (위반 시 조용히 실패)

- **User-Agent 헤더 필수.** 없으면 **403**. 일반 fetch 도구는 전부 차단된다 — 착수 시 이걸 모르면
  "SEC가 막혀 있다"는 잘못된 결론에 도달한다(실제로 이 세션에서 한 번 밟았다).
- 원본 응답은 **캐시 + 취득 meta 동반**(취득 시각·SHA-256·URL). crm AD-13 신선도 meta 계승.
  예: `2026_06_notes.zip` → sha256 `33b66c361c7300ba…`, 75,305,795 bytes.

## 2. 착수 전에 알아야 할 함정 3건 (전부 실측으로 밟음)

**① 주석 데이터셋은 2025Q3에 파일 체계가 바뀐다 — 분기 → 월간**

```
… 2024q4_notes.zip  2025q1_notes.zip  2025q2_notes.zip   ← 분기 (~410-630MB)
   2025q3_notes.zip = 404  ← 없다
   2025_07_notes.zip  2025_08_notes.zip … 2026_06_notes.zip   ← 월간 (~72-96MB)
```

분기 루프를 그대로 돌리면 **2025Q3 이후가 통째로 조용히 비어버린다.** 404가 나므로 소리는 나지만,
루프가 예외를 삼키면 최근 1년이 사라진 채 "데이터가 부족하다"는 오진에 도달한다.

**② 파일 확장자는 `.tsv`다.** SEC 문서와 다수의 서드파티 가이드가 `num.txt`·`sub.txt`로 적고 있으나
현행 아카이브는 `.tsv`다. 이름 하드코딩 금지 — 압축 목록에서 찾아 쓴다.

**③ 단일 월 표본은 10-K 계절성에 오염된다.** `2026_06`(1개월) 기준 10-K/10-Q 436건은
비가속신고자(`4-NON`)가 65%, public float 중앙값 **$16M**로 심하게 소형 편향이다 — 12월 결산
대형사는 2~3월에 몰려 신고하기 때문. **peer 셀 크기를 단일 월로 재면 거짓 결론이 나온다**
(첫 계산에서 셀 중앙값 1.0이 나왔고, 그대로 실었으면 "SEC도 커버리지 부족"이 됐다).
→ 아래 §4는 **4개 분기(2024Q3~2025Q2) 전체**로 다시 쟀다.

## 3. `sub.tsv`가 AC2·AC4 축을 전부 들고 있다 (예상 밖 수확)

peer 축과 레짐 축을 외부 소스에서 조인해 올 필요가 **없다.** 한 파일에 다 있다:

| 필드 | 의미 | 쓰임 |
|---|---|---|
| `sic` | 산업 분류 | **peer 업종 축** (AC2) |
| `afs` | filer status (`1-LAF`/`2-ACC`/`4-NON`) | **레짐 코호트 축** (AC4) |
| `pubfloatusd` | public float | SRC 임계($250M) 판정 |
| `detail` | 주석 상세 태깅 여부 | 태깅 심도 직접 측정 |
| `adsh`·`cik`·`form`·`fy`·`fp`·`period` | 식별·기간 | 조인 키 |

**조인이 하나 줄었다** — 함정4(행 오정렬) 노출면이 그만큼 작아진다.
주석 팩트는 `num.tsv`(수치)·`txt.tsv`(텍스트 블록)에 있고 `pre.tsv`의 `stmt`가 본문/주석 위치를
구분한다.

## 4. 실측 — 4개 분기(2024Q3~2025Q2), 10-K, distinct filer 5,367

### 4-1. SEC 선택의 전제가 데이터로 확인됐다

| `detail` | 건수 | 비중 |
|---|---|---|
| `1` (상세 태깅) | 5,876 | **99.9%** |
| `0` | 3 | 0.1% |

**미국은 태깅 심도에 레짐 격차가 사실상 없다.** filer status와 무관하게 99.9%가 상세 태깅이다.
DART 기각의 근거(자산 코호트별 태깅 의무 시차)가 SEC에는 **없음**이 실측으로 확인됐다 — 파티
결정의 전제가 참이었다.

> **다만 레짐 축이 0인 건 아니다.** SRC의 scaled disclosure는 *태깅 심도*가 아니라 **공시 항목
> 자체**(Reg S-K/S-X 항목, 3년 대신 2년)를 줄인다. 즉 통제해야 할 대상은 "태그를 붙였나"가 아니라
> "그 항목을 공시할 의무가 있었나"다. **레아 조건은 유효하되, 겨냥점이 바뀐다.**

filer status 분포(10-K 5,879건): `4-NON` 51.2% · `1-LAF` 35.8% · `2-ACC` 13.0%

### 4-2. peer 셀 크기 — 레짐 통제의 비용이 수치로 나왔다 (K4 직결)

| peer 정의 | 셀 수 | 셀 크기 중앙값 | n<10 셀에 갇힌 filer | n<20 |
|---|---|---|---|---|
| SIC4 | 392 | 5.0 | 19.8% | 35.3% |
| **SIC4 × filer-status** | 847 | 2.0 | **39.4%** | 52.5% |
| SIC3 | 254 | 7.0 | 11.4% | 24.8% |
| SIC3 × filer-status | 598 | 3.0 | 27.9% | 43.1% |
| SIC2 | 69 | 25.0 | 1.1% | 5.6% |
| **SIC2 × filer-status** | 192 | 9.0 | **7.8%** | 16.4% |

**핵심 긴장**: 레아가 요구한 레짐 통제는 공짜가 아니다. SIC4에서 통제를 켜면 n<10에 갇히는 filer가
**19.8% → 39.4%로 두 배**가 된다. 즉 서명(규제 시차를 워싱으로 세탁하지 않는다)과 커버리지(K4)가
정면으로 맞선다.

**단, 해소 경로가 있다**: SIC를 2자리로 롤업하면 통제를 켜고도 n<10이 **7.8%**로 떨어진다.
대가는 peer 동질성 — SIC2는 "화학 및 연관 제품" 수준의 굵은 분류라 비교 대상이 느슨해진다.

> **이건 T1이 정할 문제가 아니다.** 통계적 검정력 ↔ peer 동질성의 트레이드오프이고,
> §4-1의 발견(레짐 축의 겨냥점이 태깅 심도가 아니라 공시 의무)을 보면 **제3의 길**도 있다 —
> 셀을 통째로 쪼개는 대신 **SRC 스케일링이 실제로 건드리는 개념에만** 통제를 거는 것.
> **daria + 레아 판정 사항**으로 T2에 넘긴다.

## 5. AC1 판정

| 항목 | 결과 |
|---|---|
| frames API 도달 | ✅ |
| 재무제표 벌크 도달 | ✅ |
| **주석 레벨 도달** | ✅ — **스파이크 축소 불필요** |
| 접근 규약 문서화 | ✅ (UA 필수·캐시·취득 meta) |

**T1 통과.** "주석이 안 되면 본문 태그로만 재고 그 축소를 daria가 판정한다"는 예비 경로는
**발동하지 않는다.**

## 6. T2로 넘기는 것

1. **peer 정의 확정** — §4-2 트레이드오프에 대한 daria + 레아 판정. 후보: SIC2 × filer-status(검정력)
   / SIC3 타협 / 개념별 선택적 레짐 통제(§4-1 발견 기반).
2. **SIC의 알려진 한계 기록** — 자기신고·갱신 지연·복합기업 오분류(AC2 요구사항, 미착수).
3. **취득 창 확정** — 이 문서는 4개 분기를 썼다. 본 분석의 창(회계연도 정렬 포함)은 T3에서
   기간 정렬 문제와 함께 정한다.

## 부록 — 재현

원본 zip은 세션 스크래치패드에 캐시됨(커밋 대상 아님). 재취득은 §1 URL + UA 헤더로 충분하다.
스파이크 코드는 crm 저장소 밖에서 실행했다 — crm의 AD-4 config 가드가 저장소 전역을 스캔하므로
스파이크 산출물이 가드 표면을 오염시키지 않게 하기 위함이다(`_bmad` 선례).
