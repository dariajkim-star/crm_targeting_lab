# Spike 2 · 사전등록 — 주식보상(SBC) 부재 분해

- **일자**: 2026-07-29
- **성격**: **측정 전에 작성한다.** 이 문서가 커밋된 뒤에야 측정 코드를 돌린다.
  git 이력이 "임계가 측정을 앞섰다"를 증명한다.
- **배경**: 스파이크 1의 절차 결함(K1 임계 미설정 → 판정 절반을 daria에게 반환)의 재발 방지.
  파티 결정 ①(2026-07-29)이 정한 전방 기준을 이 개념에 **처음으로** 적용한다.

## 1. 왜 SBC인가

기존 2개념과 **구조가 다르다** — 그게 선정 이유다.

| 개념 | 재무제표 위치 | 성격 |
|---|---|---|
| 운용리스 부채 | 재무상태표 | **부채** |
| 무형자산 순액 | 재무상태표 | **자산** |
| **주식보상** | **현금흐름표(비현금 가산) + 손익계산서 배분** | **비용** |

개념 2개로 "부재 정의는 개념마다 다르다"를 주장하는 건 표본이 아니라 일화다(Sally).
비용 계정에서도 성립하는지가 이번 질문이다.

**기확인 사실(T1)**: `ShareBasedCompensation` 커버리지는 `Assets` 대비 **−27%**(4,557 vs 6,249).
격차는 이미 있다. 그게 누락인지가 이 스파이크다.

## 2. 착수 전 확정 — kill criteria (파티 결정 ① 전방 기준)

> **새 개념은 개념별 '부재' 정의를 적용한 후 ①잔차 > 0 ②개별 검증을 통과한 실명 후보 ≥ 1곳.
> 미달 시 그 개념은 스크리너에서 제외한다.**

| # | 기준 | 미달 시 |
|---|---|---|
| **S1** | 개념별 부재 정의 적용 후 **잔차 > 0** | SBC를 스크리너에서 **제외**. "비용 계정은 안 된다"가 결과 |
| **S2** | 잔차 중 **개별 검증(10-K 직접 열람) 통과 실명 ≥ 1곳** | 동일 — 제외 |

**비율 임계는 두지 않는다.** 스파이크 1에서 비율이 분모 붕괴에 놀아나는 것을 봤다(216% 사건).
"몇 %면 충분"이 아니라 **"검증을 견디는 이름이 하나라도 남는가"**가 기준이다.

**S2의 '개별 검증'이란**: 해당 filer의 실제 10-K 본문/주석을 열어 ①주식보상 비용이 정말로
어디에도 없는지 ②XBRL 태깅 사고가 아닌지 확인하는 것. 스파이크 1에서 이걸 안 해서
"본공연 몫"으로 미뤘던 항목이며, 이번엔 **표본 축소를 감수하고 실행한다**.

## 3. 착수 전 확정 — '부재'의 정의 (사후 조정 금지)

스파이크 1의 교훈 셋을 전부 선반영한다. **측정 후 이 정의를 바꾸지 않는다.**

**부재 = 아래 A·B·C가 **전부** 없을 것**

| 구분 | 태그 | 근거 |
|---|---|---|
| **A. 정본** | `ShareBasedCompensation` | 현금흐름표 비현금 가산 = 표준 총액 |
| **B. 대체 공시(상위/병렬 태그)** | `AllocatedShareBasedCompensationExpense` · `ShareBasedCompensationArrangementByShareBasedPaymentAwardCompensationCost` · `EmployeeBenefitsAndShareBasedCompensation` 등 **무차원(undimensioned)** 값 | 무형자산 umbrella 교훈(T5) 선반영 |
| **C. 파생 가능** | B 계열이 **차원(dimension) 분해로만** 존재 — 상여 유형별(RSU/옵션) 또는 비용 라인별(COGS/R&D/SG&A) | 무형자산 `Net=Gross−상각` 교훈(T3-확장) 선반영. **부분 합이 있으면 총액은 계산되는 값** |

**그리고 잔차 = 부재 ∧ 주식보상 제도 존재 증거 있음**

증거 = `ShareBasedCompensation*` / `ShareBasedPayment*` / `EmployeeServiceShareBasedCompensation*`
계열 중 **금액·수량 어느 것이든** 존재(미인식 보상원가·옵션 잔량·부여 가능 주식수 등).

**측정 규약**: 두 데이터셋(재무제표 벌크 + 주석) **합집합**(T2 계약). 4개 분기(2024Q3~2025Q2),
10-K, filing 단위. CIK 중복 제거 시 최신 결산 유지.

## 4. 착수 전 예측 — 함정 (맞았는지 사후 대조)

**crm 3-2 관례**: 착수 전에 함정을 적어두고 사후에 맞았는지 본다. 예측이 빗나가는 것도 결과다.

| # | 예측 | 왜 |
|---|---|---|
| P1 | **B(대체 태그)가 무형자산보다 더 크게 나올 것** — 잔차의 절반 이상을 먹는다 | SBC는 손익 배분 태그(`Allocated...`)가 매우 흔하고, 현금흐름표를 안 쓰는 filer가 많다 |
| P2 | **C(차원 분해만 존재)가 실질적 규모로 나올 것** | 주식보상 주석은 상여 유형별 표가 관례라 무차원 총액을 안 다는 filer가 있다 |
| P3 | **"해당 없음"이 리스보다 작을 것** | 리스는 SPAC·펀드가 구조적으로 없지만, 주식보상은 상장사면 대체로 있다 |
| P4 | **최종 잔차율이 리스(1.9%)보다 낮을 것** | B·C가 크면 남는 게 적다 |

**P1~P4가 전부 틀려도 정의는 안 바꾼다**(§3). 예측은 정의가 아니라 기대치다.

## 6. 이 문서의 구속력

- §2 kill criteria와 §3 부재 정의는 **측정 결과를 보고 수정하지 않는다.**
- 수정이 필요하다고 판단되면 **수정 사유와 함께 별도 기록**하고, 그 측정은 **탐색적(exploratory)**
  으로 강등한다 — 확증 결과로 쓰지 않는다.
- 이 규칙 자체가 스파이크 1 회고의 실행이다.
