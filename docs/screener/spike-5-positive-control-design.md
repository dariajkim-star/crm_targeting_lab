# Spike 5 · 설계 — 양성 대조군 (탐지력 검증)

- **일자**: 2026-07-29
- **성격**: **설계 문서.** 측정 전에 작성·커밋한다(스파이크2·3-V·4 방식 계승).
- **복명복창**: 표준 XBRL 금액이 안 잡히는 회사를 ①진짜 누락 ②다른 곳 기재 ③애초에 0으로 구분하고,
  **정상화하면 기업가치·재무비율·투자자 판단이 달라지는가**에 답한다.

---

## 1. 이 스파이크가 없으면 안 되는 이유

지금까지 46곳을 열어 **진짜 누락 0곳**을 얻었다. 그런데 이 결과는 **두 가지 중 어느 것인지
구분되지 않는다**:

| 해석 | 의미 |
|---|---|
| **H0 — 실제로 없다** | 미국 상장사의 공시 준수도가 높아 진짜 누락이 희소하다 |
| **H1 — 우리가 못 찾는다** | 파이프라인의 탐지력이 낮아, 있어도 못 잡는다 |

**탐지력이 0인 방법으로 46곳을 봐도 0곳이 나온다.** H1을 배제하지 못하면 §2의 "0곳"은
**탐지 결과가 아니라 미판정**이다.

> 이 프로젝트가 여섯 번 반복해 발견한 교훈이 *"부재를 증거로 착각하지 말라"*였다.
> **우리 결론이 정확히 그 실수를 하고 있는지 확인한다.**

---

## 2. 설계 — 알려진 결함 사례를 통과시킨다

**핵심**: 공시에 문제가 있다고 **제3자(SEC 또는 회사 자신)가 이미 확인한** 사례를 모아,
우리 파이프라인이 그것을 **잔차로 지목하는지** 본다.

### 2-1. 양성 사례의 출처 (전부 EDGAR 무료)

| 출처 | 서식 | 성격 | 신뢰도 |
|---|---|---|---|
| **SEC comment letter** | `UPLOAD` (SEC 발신) / `CORRESP` (회사 회신) | SEC가 **공시 미비를 직접 지적**. 회계·공시 항목별로 명시 | **최상** — 제3자 판정 |
| **재작성 공시** | `8-K` Item 4.02 (*Non-Reliance*) | 회사가 **과거 재무제표를 믿지 말라**고 스스로 공시 | 상 — 자기 인정 |
| **내부통제 중대취약점** | `10-K` Item 9A (*material weakness*) | 공시 프로세스 결함 자인 | 중 — 공시 항목과 직결되진 않음 |

**1순위 = comment letter.** 우리 표적(특정 개념의 금액 부재)과 **직접 대응**하는 유일한 출처다.

### 2-2. 양성 사례의 자격 요건 (엄격)

아무 comment letter나 쓰면 안 된다. **우리가 잡기로 한 것과 같은 종류**여야 한다:

| 조건 | 내용 |
|---|---|
| C1 | comment letter가 **금액의 부재·불충분**을 지적할 것 (문구 표현·표시 위치 지적은 제외) |
| C2 | 대상 개념이 **잔액 개념**일 것 (흐름 개념은 우리가 이미 배제 — 정당한 0 판별 불가) |
| C3 | 지적 대상 기간의 10-K가 **우리 데이터 창에 있을 것**, 없으면 그 기간으로 창을 확장 |
| C4 | **업종 동음이의 제외** 목록에 걸리지 않을 것 |

**C1~C4를 통과한 사례만 양성 대조군이다.** 통과 사례가 **0건이면 그 자체가 결과** — 우리가
정의한 종류의 결함은 SEC도 거의 지적하지 않는다는 뜻이며, H0을 간접 지지한다.

---

## 3. 판정 지표

| 지표 | 정의 | 의미 |
|---|---|---|
| **민감도(recall)** | 양성 사례 중 파이프라인이 **잔차로 지목한 비율** | **핵심 지표.** 낮으면 H1 |
| 사유 분포 | 놓친 사례가 6형태 중 어디로 잘못 분류됐는지 | 어느 규칙이 과잉 제거하는지 |
| 창 적합률 | 양성 사례 중 데이터 창에 존재하는 비율 | 측정 가능성 |

---

## 4. kill criteria (측정 전 확정)

| # | 기준 | 판정 |
|---|---|---|
| **X1** | 자격 통과 양성 사례 **≥ 5건** 확보 | 미달 시 → **탐지력 검증 불가**를 결론으로 기록. "0곳"은 미판정 상태로 영구 유지 |
| **X2** | 민감도 **≥ 50%** (양성의 절반 이상을 잔차로 지목) | 미달 시 → **H1 채택**: 파이프라인 탐지력 부족. FINDINGS의 "진짜 누락 0곳"을 **결론에서 내린다** |

**X2가 통과해야만** §2의 "0곳"이 비로소 **탐지 결과**가 된다.
**임계 50%는 지금 박는다** — 결과를 보고 정하지 않는다(스파이크1 K1 실패의 재발 방지).

---

## 5. 예상되는 난점 (착수 전 기록)

| # | 난점 | 대응 |
|---|---|---|
| N1 | comment letter는 **전문 검색이 필요**하다 (EDGAR full-text search API 이용) | `efts.sec.gov/LATEST/search-index?q=...&forms=UPLOAD` |
| N2 | comment letter의 지적이 **우리 3개 개념과 겹치지 않을** 가능성 | C1~C4 자격 심사가 곧 이 필터. 0건도 결과 |
| N3 | 지적 시점과 10-K 기간의 **시차** | comment letter는 사후에 나온다 — 대상 회계연도를 letter 본문에서 특정 |
| N4 | 표본이 작을 것 | X1(≥5건)으로 하한을 명시. 미달 시 정직하게 "검증 불가" |

---

## 6. 착수 순서

1. EDGAR full-text search로 `UPLOAD` 서식에서 리스·무형자산 관련 공시 지적 검색
2. C1~C4 자격 심사 → 양성 대조군 확정
3. 해당 회사·기간의 10-K를 우리 파이프라인에 통과 → 잔차 지목 여부 확인
4. 민감도 산출 → X1·X2 판정
5. 결과를 FINDINGS §7-1에 반영 (통과 시 "0곳"이 탐지 결과로 승격, 미달 시 결론에서 강등)

---

## 7. 구속력

§2 자격 요건 · §3 지표 · §4 kill criteria는 **결과를 보고 수정하지 않는다.**
수정이 필요하면 사유와 함께 별도 기록하고 그 측정은 **탐색적**으로 강등한다.

---

## 8. 개정 이력 (2026-07-29 1차 실행 후)

> **구속력 확인 먼저**: §2 자격 요건(C1~C4) · §3 지표 · **§4 kill criteria(X1·X2)는 그대로다.**
> 아래는 **후보 목록을 만드는 배관(plumbing)의 정정**과 **출처 우선순위 조정**이며, 통과 기준을
> 결과에 맞춰 무르는 것이 아니다.

### 8-1. 1차 실행 기록 (미완)

| 항목 | 결과 |
|---|---|
| 심사 완료 | **28 / 70** (나머지 6개 배치는 **월 사용 한도 초과**로 미실행) |
| 자격 통과 | **0** |
| 기각 | 16 |
| 판독 불가 | 12 |

**X1·X2 미판정.** 표본이 미완이고, 아래 8-2의 오염이 있어 이 28건으로는 판정하지 않는다.

### 8-2. 🔴 후보 목록 구성 오류 (정정 대상)

**EDGAR 전문검색(FTS) 결과에서 `ciks`·`display_names`와 `_id`의 accession을 잘못 짝지었다.**
28건 중 **8건이 엉뚱한 회사의 문서**를 가리켰다:

| 목록상 회사 | 실제 문서 |
|---|---|
| COVETRUS | Bitauto Holdings (Schedule 13E-3) |
| CARLISLE COMPANIES | Laird Superfood (S-1) |
| CARTERS INC | CSAIL 2019-C15 Mortgage Trust (10-K) |
| VIA optronics | Sana Biotechnology (S-1) |
| PLUG POWER (2021년 건) | New Providence Acquisition (14A) |
| Nikola Corp | **해당 accession 자체가 부존재** |

**→ 정정된 취득 방식**: FTS는 **검색용으로만** 쓰고, 후보 확정은 **회사별 `submissions` API에서
`UPLOAD` 서식을 직접 열거**해 accession↔CIK를 authoritative하게 확보한다.
FTS 히트는 "이 회사에 관련 레터가 있을 수 있다"는 **단서**로만 취급한다.

> **오염된 관찰은 결론으로 쓰지 않는다**: 1차 실행에서 "28건 중 10-K 대상은 2건뿐"이라는 분포가
> 나왔으나, 8건이 잘못된 문서였으므로 **이 분포는 깨끗한 표본의 분포가 아니다.** 기록만 하고
> 근거로 인용하지 않는다.

### 8-3. 출처 우선순위 조정 — 코멘트레터 단독 → 재작성 공시 병행

§2-1에 이미 등재돼 있던 **재작성 공시(8-K Item 4.02)를 1순위와 병행**으로 올린다.
**새 출처 추가가 아니라 우선순위 조정**이다.

- **사유**: 1차 실행에서 확인된 바, 코멘트레터의 상당수가 **등록신고서·합병 위임장**(S-1·F-1·
  S-4·14A·13E-3) 심사 건이라 **C3(10-K)에서 구조적으로 탈락**한다. 코멘트레터만으로 X1(≥5건)에
  도달하지 못할 위험이 실재한다.
- 8-K Item 4.02는 **회사가 스스로 과거 재무제표의 비신뢰를 선언**한 것이라 대상이 명확히
  정기보고서(10-K/10-Q)다. C3 적합률이 높을 것으로 예상한다.
- **자격 요건은 동일하게 적용한다** — C1(금액의 부재·오류) · C2(잔액 개념) · C3(10-K) · C4(동음이의 제외).

### 8-4. 보조 지표 추가 — 합성 대조군 (별도 라벨 필수)

실제 결함 사례가 X1에 미달할 경우를 대비해 **합성 대조군**을 보조로 둔다.

- **방법**: 실제 공시에서 표준 태그를 **인위적으로 제거**한 뒤 파이프라인이 잔차로 지목하는지 확인.
- **측정하는 것**: **탐지력의 상한**(ceiling). 규칙이 논리적으로 작동하는지.
- **측정하지 못하는 것**: 실제 세계의 민감도. 실제 결함은 태그 제거보다 복잡하다
  (다른 곳 기재·부분 공시·업종 동음이의가 뒤섞인다).
- **🔒 라벨 규약**: 합성 결과는 **X2 판정에 산입하지 않는다.** 별도 지표(`synthetic_ceiling`)로만
  보고하며, "민감도"라는 이름을 쓰지 않는다. 산입하면 우리가 여섯 번 잡아낸 실수 — **쉬운 증거로
  어려운 질문에 답하기** — 를 우리가 저지르는 것이다.

### 8-5. 남은 리스크 (착수 전 기록)

| # | 리스크 |
|---|---|
| R1 | 정정된 방식으로도 자격 통과가 5건 미만일 수 있다 → **X1 미달을 결과로 기록**하고, "탐지력 검증 불가"를 FINDINGS §7-1에 영구 명시 |
